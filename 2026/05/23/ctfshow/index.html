过滤了所有数字字母并只剩下了 |或这个运算符

异或，自增，取反分别是什么

绕过手段 核心符号 使用条件（过滤规则） 核心原理
异或绕过 ​^​ 题目没有过滤异或符号^​，且能提供两个未被过滤的字符进行碰撞。 利用 PHP 字符串的位运算特性。两个未被过滤的字符（如!​和@​）转换成二进制后逐位异或，结果恰好等于被过滤的目标字符（如a​）。
取反绕过 ​~​ 题目没有过滤波浪号~​，通常用于过滤了绝大多数可见字符的极端场景。 利用 ASCII 码的按位取反特性。一个不可见的特殊字符（或 URL 编码后的乱码）经过​运算后，会还原成正常的字母或数字（如%8F​还原为p​）。
自增绕过 ​++​ 题目没有过滤点号.​、下划线_​、中括号[]​等用于构造初始字符的符号。 利用 PHP 字符自增的推导特性。先通过隐式转换（如数组转字符串得到 “Array”）拿到初始字母 “A”，再通过++​依次推导出 B、C、D… 从而拼出目标单词。

在 CTF Web 类的命令执行（RCE）题目中，“异或”是一种非常经典且强大的​绕过过滤（Bypass）技巧​。

当题目代码对用户的输入进行了严格的限制（例如过滤了所有的字母、数字或某些特殊符号），导致你无法直接输入 system​、cat​、flag​ 等常规命令时，就可以利用 PHP 中的异或运算符 ^​ 来“凭空构造”出这些被禁用的字符。

💡 异或绕过的核心原理

在 PHP 中，两个字符串进行异或运算时，会先将它们的字符转换为对应的 ASCII 码（二进制形式），然后逐位进行异或运算，最后再将结果转换回字符。

利用这个特性，我们可以寻找两个​没有被过滤的、看起来毫无意义的特殊字符​，让它们异或后恰好等于我们想要的字母或数字。

举个具体的例子：假设题目过滤了所有的字母，但我们想执行 phpinfo()​ 函数。

  • 字符 A​ 的 ASCII 码是 65，二进制为 01000001​。
  • 字符 r​ 的 ASCII 码是 114，二进制为 01110010​。
  • 将两者进行异或运算：01000001 ^ 01110010 = 00110011​。
  • 二进制 00110011​ 对应的十进制是 51，在 ASCII 码表中对应的字符正是数字 3​。
    所以，在 PHP 代码中 "A"^"r"​ 的结果就是 "3"​。同理，我们可以通过编写脚本，遍历所有可见字符，找到能异或出 s​, y​, s​, t​, e​, m​ 等字母的字符组合，最终拼凑出 system("cat /flag")​ 这样的完整命令。

在真实的 CTF 比赛或解题中，你经常会看到类似下面这种像“乱码”一样的 Payload，这就是典型的异或绕过：

这段代码看起来非常复杂，但它实际上就是通过异或运算，在服务器内存中动态还原出了类似 system('ipconfig')​ 或 system('cat flag')​ 的命令并执行。

🛡️ 为什么攻击者（出题人）喜欢用异或？

除了绕过 WAF（Web应用防火墙）或题目的正则过滤，异或在安全领域还有以下作用：

  • ​代码混淆与免杀​：恶意软件或 Webshell 经常使用异或来加密关键的敏感字符串（如 cmd.exe​、eval​ 等）。因为异或运算具有可逆性（A ^ B ^ B = A​），在代码执行时再解密还原，可以有效躲避杀毒软件基于特征码的静态查杀。
  • ​隐蔽性强​：异或生成的 Payload 通常由大量不可见字符或特殊符号组成，不仅绕过了字母数字限制，也让防御人员很难一眼看出攻击者的真实意图。
    简单来说，在 CTF Web 命令执行中，异或就是一把“字符变形钥匙”，它能让你在极其受限的环境下，用允许的符号组合出被禁止的命令，从而成功拿到 Flag。

📈 自增（Increment）：用 ++​ 凭空造出字母

核心原理：PHP 有一个非常独特的特性：​字符可以进行自增运算，并且会按照 ASCII 码表的顺序向后推导​。 比如：'A'++​ 的结果是 'B'​，'a'++​ 的结果是 'b'​。

绕过思路：既然不能直接输入字母，那我们就想办法搞到任意一个字母作为“种子”，然后通过不断地 ++​ 自增，推导出我们需要的其他字母。

  • 如何获取第一个“种子”字母？通常利用 PHP 的隐式类型转换。例如，将一个空数组 []​ 转换成字符串会变成单词 "Array"​。
    • 代码逻辑：$_ = [] . '';​ 此时 $_​ 的值就是字符串 "Array"​。
    • 提取首字母：$_ = $_[0];​ 此时 $_​ 的值就是大写字母 "A"​。
  • 如何构造出想要的单词（如 POST​）？拿到 "A"​ 之后，就可以通过多次自增变成 S​、Y​、S​、T​、E​、M​ 等，再用点号 .​ 把它们拼接起来。

为什么 c=tac%09fla?.php||ls​ 能成功，而 %0a​ 不行？为什么 $IFS$9​ 又可以？这背后的核心原因在于 Shell 对字符的解析机制 以及 ​system()​ 函数执行命令的方式​。

🛡️ 为什么 %0a 不行，而 %09 可以？

首先我们要知道，%09​ 是 Tab（制表符） 的 URL 编码，而 %0a​ 是 换行符（Line Feed） 的 URL 编码。

当你的 Payload 传入后，服务器上的 PHP 代码 system($c." &gt;/dev/null 2&gt;&amp;1");​ 会把你的输入和后面的重定向语句拼接起来一起丢给 Linux 的 Shell 去执行。

  • 当你使用 %09​ (Tab) 时：
    在 Linux Shell 中，Tab 和空格一样，都被视为​参数分隔符​。
    服务器实际执行的命令类似于：tac[TAB]fla?.php||ls &gt;/dev/null 2&gt;&amp;1​
    Shell 能够完美理解 tac​ 是命令，fla?.php​ 是参数，中间的 Tab 只是用来隔开它们的。所以命令能正常执行，你也能看到回显。
  • 当你使用 %0a​ (换行) 时：
    在 Linux Shell 中，换行符是一个​命令终结符​。它的作用等同于你敲了一下回车。
    服务器实际执行的命令被换行符强行截断成了两行：
    • 第一行： tac​ （注意，后面没有任何参数）
    • 第二行： fla?.php||ls &gt;/dev/null 2&gt;&amp;1​
      结果就是： Shell 先执行了第一行的 tac​。因为 tac​ 命令后面没有跟任何文件名，它会默认等待标准输入（卡住或报错）。紧接着，第二行的 fla?.php​ 会被 Shell 当作一个新的命令去尝试执行。但 fla?.php​ 只是一个文件名，并不是可执行程序，所以系统会报错提示 command not found​。因此，你的 Payload 就失效了。

💡 为什么 $IFS$9 也可以？

这就涉及到了 Linux Shell 的一个内置变量 $IFS​（Internal Field Separator，内部字段分隔符）。

  • ​$IFS​ 的默认值就包含了空格、Tab 和换行符。
  • ​$9​ 是一个位置参数，在普通的命令执行中它通常是空的。
    当你写 $IFS$9​ 时，Shell 会先解析变量。因为 $9​ 是空的，所以 $IFS$9​ 最终就被解析成了 $IFS​，也就是一个​空格或制表符​。Shell 把它当作参数之间的分隔符，所以 tac$IFS$9fla?.php​ 就等同于 tac fla?.php​，自然就能成功执行了。

📌 总结一下

  • ​%09​ (Tab) 和 $IFS$9​：在 Shell 眼里是“空格”，用来隔开命令和参数，所以能绕过空格过滤。
  • ​%0a​ (换行)​：在 Shell 眼里是“回车”，会把你的完整命令强行拆成两段，导致命令执行逻辑错乱。
    小建议：
    在 CTF 的命令执行（RCE）题目中，绕过空格过滤的“万金油”通常是 %09​、$IFS$9​、${IFS}​ 。而 %0a​ 通常用在另一种场景：当题目过滤了分号 ;​，你可以用 %0a​ 来代替分号，实现执行完一条命令再执行下一条（比如 127.0.0.1%0als​）。

$’\xxx\xxx\xxx\xxx’原理

​$'\xxx\xxx\xxx\xxx'​ 这种写法，在 Linux Bash 环境中有一个非常专业的术语，叫做 ​ANSI-C 引号（ANSI-C Quoting）​。

它的核心原理其实非常简单，就是“披着数字外衣的字符翻译器”。我们可以从以下三个维度来彻底拆解它：

1. 核心语法拆解

  • ​$’…’​（翻译开关）​：这是 Bash 的一个特殊语法。它的作用是告诉系统：“请把单引号里面的内容，按照 C 语言的标准进行转义（翻译）”。普通的单引号 '...'​ 里面的内容会被当成纯文本，而加上 $​ 之后，引号里的转义序列就会被激活。
  • ​\xxx​（字符的八进制伪装）​：这里的 \​ 是转义符，后面的 xxx​ 是 ​1到3位的八进制数字​。每一个八进制数字都对应 ASCII 码表里的一个真实字符。
    • 比如：a​ 的 ASCII 码十进制是 97，换算成八进制就是 141​。所以 \141​ 就会被 Bash 还原成 a​。

2. 它是怎么一步步执行的？

当你输入 $'\143\141\164'​ 并按下回车时，Bash 在底层做了以下动作：

  • ​识别开关​：Bash 发现了 $'...'​ 结构，知道这里面藏着需要翻译的暗号。
  • ​查表翻译​：它依次读取里面的八进制数：
    • ​\143​ -> 查 ASCII 表 -> 翻译为 c​
    • ​\141​ -> 查 ASCII 表 -> 翻译为 a​
    • ​\164​ -> 查 ASCII 表 -> 翻译为 t​
  • ​还原执行​：翻译完成后，这串代码在内存中变成了 cat​。随后，Bash 把它当作一个正常的系统命令去执行。

3. 为什么它能绕过 WAF（防火墙）？

这就是它在 CTF 和漏洞利用中最大的价值所在：

  • ​视觉欺骗​：对于很多简单的防火墙或代码过滤器来说，它们只会在黑名单里查找 cat​、ls​、bash​ 这样的​明文字母​。
  • ​完美绕过​：而 $'\143\141\164'​ 里面​一个字母都没有​，只有数字、反斜杠和引号。防火墙看了一眼觉得“这只是一串奇怪的数字，不是危险命令”，于是放行。等流量到了服务器底层，Bash 才会把它还原成真正的 cat​ 命令执行。
    💡 补充一个小知识：除了八进制（\xxx​），这种语法其实也支持十六进制（\xhh​）。 比如 A​ 的十六进制 ASCII 码是 41​，所以 $'\x41'​ 同样会被翻译成 A​。但在 CTF 的无字母命令执行中，八进制因为字符长度和绕过特性的优势，被使用得更加频繁。

为什么在网页里面能够执行linux命令

Linux Bash 环境绝对不是普通网页的一般环境。

我们平时上网浏览网页（普通网页环境），是通过浏览器（Chrome、Edge等）发送请求，服务器上的 Web 软件（如 Nginx、Apache）接收请求后，返回 HTML、CSS 等文件，浏览器再把这些代码渲染成你看到的精美页面。

而你在 CTF 题目或漏洞利用中遇到的“URL 命令执行”，是因为目标网站的代码存在严重的​安全漏洞​。攻击者（或解题者）通过精心构造的 URL，欺骗了服务器，让服务器在后台偷偷调用了 Linux 的 Bash 环境去执行你指定的系统命令。

为了让你更清晰地理解，我们可以从以下三个方面来拆解：

1. 本质上的天壤之别

  • ​普通网页环境（浏览器端）​： 你看到的网页是运行在你的电脑浏览器里的。浏览器是一个高度受限制的“沙盒”环境，它只能负责展示页面、播放视频或运行前端的 JavaScript 代码，绝对没有权限去操作服务器底层的 Linux 系统，更不能随意调用 Bash 执行命令（否则你的电脑早就被网页病毒攻陷了）。
  • ​URL 命令执行环境（服务器端）​： 这发生在远程的 Linux 服务器上。当 URL 中的命令被执行时，意味着服务器端的 Web 应用程序（比如用 PHP、Python 写的网站后台）调用了系统级的函数（例如 PHP 中的 system()​, exec()​, shell_exec()​ 等）。这些函数会直接唤醒服务器底层的 Bash，去执行你传入的指令。

2. 为什么 URL 命令执行都在 Bash 环境里？

因为绝大多数提供 Web 服务的服务器，底层运行的都是 Linux 操作系统，而 ​Bash 正是 Linux 系统默认的“指挥官”（命令解释器）​。

当 Web 应用程序需要调用系统命令时，它的执行流程是这样的：

  • ​Web 程序​（如 PHP）接收到你的恶意请求。
  • Web 程序调用系统函数（如 system($c)​）。
  • 操作系统接收到调用请求，启动默认的 ​Shell（也就是 Bash）​。
  • Bash 解析你传入的字符串（比如我们之前聊的 $'\154\163'​），然后去执行真正的 Linux 命令。
    所以，并不是 URL 天生就能执行 Bash 命令，而是因为服务器底层是 Linux，且 Web 程序存在漏洞，把控制权交给了 Bash。

3. 一个直观的对比

特性 普通网页浏览 URL 命令执行 (CTF/漏洞场景)
发生位置 你的本地电脑（浏览器） 远程的 Linux 服务器后台

权限范围 仅限网页内容展示，无法触碰系统 拥有服务器当前用户的系统权限（如读写文件）

总结一下：你在 URL 里执行 Bash 命令，本质上是在​远程操控服务器后台的 Linux 终端​。这在正常的互联网产品中是绝对不允许出现的严重安全漏洞（通常被称为 RCE，远程命令/代码执行漏洞），但在 CTF 比赛中，它被设计成一种考察你对 Linux Bash 底层原理和系统安全理解的经典题型。

​$(())​ 是 Linux Bash Shell 中的算术扩展（Arithmetic Expansion）语法，专门用来进行整数运算。在 CTF 的无字母数字命令执行（RCE）题目中，它是绕过数字过滤的绝对神器。

🛠️ 核心原理：如何凭空构造数字？

它的核心玩法基于以下三个 Bash 特性：

  • ​$(())​ 或 $((0))​ 的值为 0​：即使里面什么都不写，它的默认值也是 0。

  • ​​ 是按位取反运算符​：在计算机中，对 0​ 进行取反运算（`0​），结果会变成 -1`​。

  • ​加减法运算​：在 $(())​ 里，多个数字连在一起默认是做加法（例如 $((-1-1))​ 等于 -2​）。
    推导公式如下：

  • ​$(())​ = 0

  • ​$((~$(())))​ = ** -1 ** （对 0 取反）

  • ​$((~$(())))$((~$(())))​ = ** -2 ** （即 -1 + -1）

  • 以此类推，只要不断叠加 $((~$(())))​，就能构造出任意负数。

  • 最后，再在最外层套一个 ~​ 进行取反，就能把负数变回我们想要的正整数（例如 ~(-37)​ = ​36​）。

0取反得到-1的原理

在计算机的底层世界里，0 取反变成 -1 并不是魔法，而是由二进制按位取反和补码（Two’s Complement）的数学规则共同决定的。我们可以通过以下三个步骤来彻底理解这个过程：

💡 1. 直观表现：按位取反（~）

在计算机中，数字是以二进制（0和1）的形式存储的。

  • ​0 的二进制​：无论计算机用 8 位、32 位还是 64 位来存储，0 的每一位全都是 0。
    以 8 位为例：0000 0000​
  • ​按位取反操作（~）​：就是简单粗暴地把所有的 0 变成 1，所有的 1 变成 0。
    对 0 取反后：1111 1111​
    现在问题来了：计算机看到 1111 1111​ 这串二进制时，为什么认为它是 -1 呢？这就涉及到计算机存储负数的规则——补码。

🧮 2. 核心规则：补码（Two’s Complement）

现代计算机为了简化硬件设计（让加法器也能做减法），统一使用补码来表示有符号整数。补码的核心规则是：

  • ​最高位是符号位​：0 代表正数，1 代表负数。

  • ​负数的绝对值计算​：如果你看到一个最高位是 1 的二进制数（负数），想知道它具体是负几，需要再次对它进行“取反加一”的操作。
    我们来看看 1111 1111​ 是怎么被解读为 -1 的：

  • ​看符号位​：最高位是 1​，说明这是一个负数。

  • ​求绝对值​：对 1111 1111​ 进行“取反加一”。

    • 取反：0000 0000​
    • 加一：0000 0000​ + 1 = 0000 0001​ （也就是十进制的 1）

  • ​得出结论​：符号是负，绝对值是 1，所以 1111 1111​ 就是 ​**-1**​。

📐 3. 数学公式：~x = -(x + 1)

从数学推导上，按位取反运算有一个通用的恒等式：​~x = -(x + 1)​。
这个公式对任何整数都成立，我们可以直接套用来验证：

  • 当 x = 0 时：~0 = -(0 + 1) = -1​
  • 当 x = 5 时：~5 = -(5 + 1) = -6​
  • 当 x = -5 时：~-5 = -(-5 + 1) = -(-4) = 4​
    所以，0 取反得到 -1，既是二进制位翻转的直接结果，也是计算机补码数学体系的必然规律。
